POST /v1/orders Submit a trade order

Required header

Idempotency-Keyrequired

Any unique string per request. Duplicate submissions with the same key return the original response without re-processing.

Request body

{
  "accountId": "ACC-001",
  "symbol": "AAPL",
  "side": "BUY",
  "quantity": 10,
  "price": 175.50
}

Response — 201 Created

{
  "id": "b4f0c2a1-...",
  "accountId": "ACC-001",
  "symbol": "AAPL",
  "side": "BUY",
  "quantity": 10,
  "price": 175.50,
  "status": "PENDING",
  "createdAt": "2026-11-11T09:00:00Z"
}

Validation rules

FieldConstraint
accountIdrequired, non-empty string
symbolrequired, non-empty string
sideBUY or SELL
quantitydecimal > 0
pricedecimal > 0

GET /health/live   /health/ready Health probes

Liveness — always 200

{ "status": "alive" }

Readiness — 200 when ready

{ "status": "ready" }

Idempotency

How it works: Every POST /v1/orders call must include an Idempotency-Key header. If a request arrives with a key that already exists in the database, the original order is returned immediately — no duplicate insert, no error. This makes retries safe: a network failure won't create phantom duplicate orders.

First request

POST /v1/orders
Idempotency-Key: order-abc-123

→ 201 Created
   { "id": "b4f0c2a1-...", "status": "PENDING" }

Retry with same key

POST /v1/orders
Idempotency-Key: order-abc-123

→ 201 Created
   { "id": "b4f0c2a1-...", "status": "PENDING" }
   (same response, no duplicate)
