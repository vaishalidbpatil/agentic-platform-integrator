Local Development

Prerequisites, setup, and common troubleshooting.

Prerequisites

🐳

Docker Desktop

Running with Docker Engine accessible. Required for PostgreSQL and API containers.

⚡

.NET 10 SDK

For local dotnet run without Docker. Download from dotnet.microsoft.com.

🖥️

PowerShell 7+

Required to run setup.ps1. Included with Windows 11; install on macOS/Linux via GitHub.

Option A — Full Docker stack (recommended)

Runs Postgres and the API together in Docker. setup.ps1 handles everything.

1

Run the setup script

# From repo root in PowerShell
.\setup.ps1
2

What the script does

① docker compose down --remove-orphans -v — cleans up all containers and volumes for a fresh start
② docker compose up -d postgres — starts PostgreSQL 16
③ Polls pg_isready until the database accepts connections
④ docker compose up -d --build api — builds the .NET 10 image and starts the API (MigrationRunner applies all schema on startup)

3

Verify

# Health check
curl http://localhost:8080/health/live

# Open Swagger in browser
http://localhost:8080/swagger

Option B — Local dotnet run (faster iteration)

Start only Postgres in Docker, run the API natively for fast rebuild cycles and debugger support.

# Start Postgres only
docker compose up -d postgres

# Run the API locally (uses appsettings.json → Host=localhost)
dotnet run --project src/Portfolio.TradeOrderService.Api

Migrations run on startup here too — same MigrationRunner path.

Common errors & fixes

ErrorCauseFix
Database is uninitialized and superuser password is not specified A stale postgres_data volume exists from a failed previous init — Postgres won't re-read env vars on an already-initialised volume. Run .\setup.ps1 — it calls docker compose down -v to wipe the volume, then starts fresh.
volume is in use - [container id] A container is still holding the volume, preventing removal. setup.ps1 uses --remove-orphans and force-removes the holding container before deleting the volume.
NETSDK1045: does not support targeting .NET 10.0 Dockerfile was using the .NET 9 SDK image while projects target net10.0. Dockerfile now uses mcr.microsoft.com/dotnet/sdk:10.0 and aspnet:10.0. No action needed.
addgroup: not found The aspnet:10.0 runtime image is Debian-based, not Alpine — uses groupadd/useradd not addgroup/adduser. Dockerfile now uses groupadd --system appgroup && useradd --system --gid appgroup appuser. No action needed.
relation "orders" already exists Postgres volume persisted tables from a previous run, but __migrations records were missing, so the runner tried to re-create them. Migration SQL files now use IF NOT EXISTS on all CREATE TABLE and CREATE INDEX statements. No action needed.
Connection refused 127.0.0.1:5432 Running dotnet run locally but Postgres container isn't started. Run docker compose up -d postgres first, then dotnet run.
