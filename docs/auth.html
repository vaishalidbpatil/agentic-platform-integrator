Auth Service OAuth 2.0 OIDC

Standalone identity server powered by Duende IdentityServer 8. Issues JWTs for machine-to-machine and browser clients.

Overview

Auth.Service is a containerised OAuth 2.0 / OpenID Connect token server. It has no login UI — it is a pure token issuer for service-to-service (client credentials) flows and will back the browser dashboard via PKCE (authorization code).

Getting a Token (client_credentials)

Use this to call the Orders API from a script or test:

# Request a token
curl -X POST http://localhost:5001/connect/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&client_id=orders-api-client&client_secret=orders-api-secret&scope=orders.read%20orders.write"

# Response
{
  "access_token": "eyJhbGci...",
  "expires_in": 3600,
  "token_type": "Bearer",
  "scope": "orders.read orders.write"
}

# Use the token
curl http://localhost:8080/v1/orders \
  -H "Authorization: Bearer eyJhbGci..."

Signing Credential

In development, Auth.Service uses .AddDeveloperSigningCredential() — a temporary RSA key written to disk on first start. This is fine for local development and demos.

Production: Replace with an X.509 certificate loaded from a secret store (Azure Key Vault, AWS Secrets Manager, Kubernetes secret). Never ship developer signing credentials to production.
