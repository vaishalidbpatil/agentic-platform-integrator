Project structure

Nine projects across a layered .NET 10 solution. Dependencies only flow inward — outer layers never reference inner layers.

ProjectResponsibility
Api ASP.NET Core host. Controllers, middleware, DI registration, health endpoints, rate limiting, Swagger. Entry point for all HTTP traffic.
McpServer Standalone MCP tool server exposing 4 tools: get_order_status, list_recent_orders, get_data_quality_report, replay_dead_letter_message. Read-only by default with an approval gate and full audit log.
ServiceInterfaces Contracts only — IOrderService, IIngestionService, etc. No implementations. Allows the Api to depend on abstractions without coupling to business logic.
Services Implementations of service interfaces. Contains all business logic: order validation, idempotency checks, status transitions.
Sync Background service that polls the outbox table for PENDING events and publishes them to RabbitMQ. Decouples DB writes from message publishing. Marks events SENT on success, increments attempts on failure.
Models Shared domain models (Order, OrderSide, OrderStatus), DTOs, enums, and request/response contracts. No external dependencies.
Database Migration runner and embedded SQL schema files. Loads *.sql files as assembly resources, runs unapplied ones in order, tracks applied migrations in a __migrations table.
DataAccess Repository implementations (OrderRepository). All SQL lives here — raw Npgsql, no ORM. The outbox event insert happens atomically in the same transaction as the order insert.
Configuration Strongly-typed option classes (DatabaseOptions, RabbitMqOptions, S3Options). Bound from appsettings.json at startup.
